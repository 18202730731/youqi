# 有期 · 证件到期提醒助手

Taro 4.3 + React 18 + TypeScript。微信小程序与 H5 共用业务与界面；无账号密码、证件号、照片上传或第三方统计。

## 已实现

- 证件卡片、状态统计、按成员/状态筛选、文字搜索、三种排序。
- 8 类证件模板与自定义记录，新增/编辑/删除、发证日期与有效期、1–365 天提前提醒。
- 详情倒计时、办理材料核对、注明来源的政府链接、官方办理入口复制。
- 月历同时展示到期日与提前提醒日，可切换月份、选择日期查看相关证件。
- 家庭成员昵称与颜色管理，最多 5 人（含自己）；有证件的成员需要先转移证件才可删除。
- 默认本地保存，输入与存储数据校验；保存失败不会显示成功。首个真实记录自动清空示例。
- 隐私说明、明确确认的数据清理、H5 打印/保存 PDF 清单。
- 微信云函数 `sync` 与 `reminders`、按 OPENID 隔离、显式云同步授权、云端恢复与删除、一次性订阅调用、定时提醒任务。
- 桌面/手机适配，键盘聚焦、弹窗 Escape/焦点循环、减少动态效果设置。

## 本地运行

使用 Node.js 22 或 24；本项目已使用 Node.js 24 验证。项目自带 npm 锁文件。

```powershell
npm ci --legacy-peer-deps
npm run dev
```

H5 开发地址 `http://127.0.0.1:4173`。

```powershell
npm run typecheck
npm test
npm run build
npm run preview
npm run build:weapp
```

`dist/` 为 H5；`dist-weapp/` 为小程序。构建配置移除了与新 Webpack 不兼容的进度条插件，不影响应用功能。若受到系统沙箱的目录读取限制，需要允许构建工具访问项目路径；无需修改业务代码。

## 微信云开发接入

当前交付未绑定微信账号、AppID、云环境或支付商户。网页版保持纯本地模式，云同步和微信订阅按钮按真实能力禁用。云函数已做语法检查，仍需以下步骤与真机联调后才能上线。

1. 将 `project.config.json` 的 `touristappid` 替换为你的小程序 AppID，在微信开发者工具导入此目录，创建并关联云开发环境。
2. 复制 `.env.example` 为 `.env.local`，填写 `TARO_APP_CLOUD_ENV` 与已获批的一次性订阅模板 `TARO_APP_REMINDER_TEMPLATE`。环境 ID 和模板 ID 不是密钥；请勿把服务端密钥写入前端。
3. 创建 `youqi_profiles`、`youqi_reminders` 集合。分别在数据库权限中设置客户端读写均禁止（参考 `cloudfunctions/database.rules.json`）。访问仅通过云函数，由 `cloud.getWXContext().OPENID` 决定用户身份，忽略客户端身份输入。
4. 在开发者工具中对 `sync`、`reminders` 选择“上传并部署：云端安装依赖”。两者设置相同的 `REMINDER_TEMPLATE_ID`，与前端模板 ID 一致。
5. 对 `reminders` 设置模板实际字段名：`REMINDER_NAME_FIELD`（证件名称，建议 thing 类型）、`REMINDER_DATE_FIELD`（到期日，date/time 类型）、`REMINDER_HOLDER_FIELD`（持有人昵称，建议 thing 类型）。示例代码要求这三个不同字段。应选择与你类目相符、可承载这些字段的获批模板；字段数量、类型或格式不同需按真实模板调整发送映射，不能编造模板 ID。测试时可设 `MINIPROGRAM_STATE=developer`，上线后为 `formal`。
6. 上传 `reminders/config.json` 中的触发器，默认表达式为每天 09:00。部署时在控制台核对触发器时区；目标为北京时间 09:00，若控制台以 UTC 解释，应将小时改为 01。日期计算统一使用北京时间。
7. 为提醒集合创建复合索引 `state` 升序 + `notifyDate` 升序。真机先添加测试证件、开启云同步，然后在详情点击“订阅一次”。前端等待本地同步完成后记录订阅任务。
8. 测试至少两个微信账号的数据隔离，以及拒绝订阅、模板字段错误、删除云副本、修改到期日、重复定时调用和发送失败。

### 同步与消息语义

同步是手动开启后的整份快照覆盖，首次开启以当前设备为准；云端恢复需要确认，不做无提示的跨设备覆盖。不提供多人实时协作。成员分类不会邀请家人或共享数据。

每份证件的任务键包含 OPENID、证件 ID、到期日与提醒天数。更改日期、提醒天数或删除证件会移除旧任务，需重新授权。发送前再次检查证件是否仍存在且日期未变，并用事务抢占防止并发重复发送。已过期记录不再创建通知任务。

提醒函数每次最多处理 100 条任务，生产量增长后需加入游标批处理、队列与监控。`failed`、长期 `sending` 任务保留给运营检查，不盲目自动重发，避免网络超时但已送达时重复消费一次性授权。不能承诺微信消息必达，也不能承诺外部发送与数据库写入的严格原子性。

关闭云同步停止后续上传，但已有云端副本与任务仍保留；如需停止云端提醒，请在设置中“删除云端副本”。本地清空不会悄悄删除云端。生产环境需要增加自助云端诊断及通知授权状态展示。

## 隐私与办理指引

仅保存证件名称、发证日/到期日、提醒天数、成员昵称、备注及应用内部随机 ID。不提供图片上传或证件号字段；备注中也请勿填写敏感信息。本地存储不是加密保险箱，清理应用数据可能造成丢失。

身份证与驾照材料以已标注的浙江/北京官方指南作为地方示例；护照引用国家移民管理局。居住证、签证、车辆年检不编造全国统一材料与周期，提供官方核实入口。保险仅提示核对保单和联系承保机构，不提供销售或报价。所有预约都在官方平台完成，打开入口不代表预约成功。

## 商业化边界

内测版开放本地功能，没有伪支付、付费墙、流量主广告或自动扣费。原方案的 3 元/月、29 元/年可作为后续价格假设，不等于已接入微信支付或获批自动续费。

会员收费上线前需确认小程序主体、服务类目、商户号及可用支付能力，再实现服务端下单、验签回调、订单幂等与服务端权益校验。不能仅用前端开关解锁付费权益。长期微信订阅消息也不能默认可用；当前按一次授权一次通知实现。
